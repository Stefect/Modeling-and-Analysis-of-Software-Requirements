# Специфікація вимог: Маркетплейс (Завдання 2)

## 1. Намір (Intent)
Формалізувати та структурувати функціональні вимоги до мультивендорного маркетплейсу, побудувати сценарії використання (Use Cases) та забезпечити повну трасованість вимог до сутностей даних із Завдання 1 (`USER`, `STORE`, `PRODUCT`, `ORDER`, `ORDER_ITEM`, `REVIEW`)[cite: 18, 24].

## 2. Актори (Actors)
- **Людина (Human Actors):**
  - `User` (Абстрактний користувач системи — узагальнення).
  - `Customer` (Покупець, успадковує `User`): шукає товари, додає їх у кошик, оформлює замовлення (`ORDER`), залишає відгуки (`REVIEW`)[cite: 18].
  - `Seller` (Продавець, успадковує `User`): володіє магазинами (`STORE`), керує каталогом товарів (`PRODUCT`)[cite: 18].
- **Зовнішня система (External System):**
  - `Payment Gateway` (Платіжний шлюз): обробляє транзакції та підтверджує статус оплати чека.

## 3. Критерії прийняття (Acceptance Criteria)
- **Формат EARS:** Вимоги сформульовані за термінологією EARS (Ubiquitous, Event-driven, State-driven, Optional, Unwanted behavior)[cite: 24].
- **Зв'язок із даними Завдання 1:** Усі Use Cases та вимоги прямо мапляться на сутності `USER`, `STORE`, `PRODUCT`, `ORDER`, `ORDER_ITEM`, `REVIEW`[cite: 18, 24].
- **Use Case Diagram:** Діаграма Mermaid містить $\ge 2$ типи акторів, зв'язки `<<include>>`, `<<extend>>` та узагальнення акторів[cite: 24].
- **Матриця трасування:** Зв'язки N:M між вимогами EARS та Use Cases; присутня $\ge 1$ непокрита вимога з поясненням межі системи[cite: 24].
